P1 · F2

The running Python worker did not demonstrate model-backed research

The existing worker launched without DASHSCOPE_API_KEY or OPENAI_API_KEY. Its database loader reads only DATABASE_URL from .env. Both completed briefs match the deterministic fallback text; the API, which loads .env separately, successfully used Qwen for lead planning/qualification.

Why it matters. Completed research and a ready brief do not prove that the Python model path ran. This is a finding about the tested local worker environment; production was not inspected.

Next check. Start the worker with its configured provider environment and rerun both goals. Make active model/fallback mode visible in health or job metadata. No environment or server configuration was changed in this audit.

P2 · F3

A FAQ question was stored and cited as factual evidence

Both briefs include the question “What is Jonathan Windham’s role at Blackhawk Digital Marketing?” as a key signal and talking point. It resolves to stored evidence, but it is not a factual assertion.

Why it matters. Citation integrity passes while semantic evidence quality fails. In each initial brief this was one of only two displayed key signals.

Next check. Exclude interrogative/FAQ fragments and pair answers with their questions before extraction; test this case in both fallback and model paths.

P2 · F4

Malformed workspace names return HTTP 500

Authenticated PATCH /workspace-settings with {"name":123} or {"name":{"invalid":true}} returns 500 Internal server error rather than a validation response.

Why it matters. An ordinary bad request reaches name?.trim() with a non-string value. The server stays available, but the endpoint handles typed input inconsistently with CRM DTO validation.

Next check. Validate the request with a DTO or a string type check before trimming; return HTTP 400.
